## Incremental parity evidence

- Issue #114 extends PRESENT-001 with Ginmaku's `空白⇔表示` behavior. Direct
  protocol and component tests plus the latest-Chromium two-tab E2E verify
  blank, navigation while blank, and display of the latest location after
  unblank.

## Matrix maintenance rules

- One row is one independently verifiable capability; split compound rows as
  evidence improves.
- Priority changes require a dated reason and owner. Never delete a `won't` row.
- Replace path-only evidence with approved runtime/golden evidence when obtained,
  but retain the pinned source link.
- `verified` requires automated evidence on Levi and resolution of every blocker;
  implementation or a screenshot alone is insufficient.
